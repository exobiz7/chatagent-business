## Scope and contract
- The prior F04 recovery path correctly linked a copy reservation to the same HMAC-sealed action/processId without replay, but legacy `config.json` recovery checked only nonce/processId/dev/ino and the *reconstructed* copy intent. It did not hash the actual runner config executable/argv/cwd/timeoutMs. Astra's fixture observed 11 altered fields accepted and bound.
- `scripts/l1/async-copy-jobs.mjs` now validates the actual private, no-follow and size-bounded config's typed `executable`, `argv`, `cwd`, `timeoutMs`, nonce and processId. It hashes the **actual persisted execution fields** in the same fixed key order used by `DurableHostProcesses.start` and requires equality with the original HMAC-sealed `action.digest`.
- It then separately verifies the independently reconstructed copy intent (original source/destination/source SHA/size/helper/stage plus dev/ino from the validated config) against the same action digest. Missing fields, wrong types, unexpected contents and mismatched digests refuse `ASYNC_COPY_RECONCILIATION_REQUIRED` before mutating copy binding/audit. No new process, stage or copy effect is created.
