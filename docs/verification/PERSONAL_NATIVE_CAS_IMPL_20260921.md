# Personal native existing-file replacement — implementation checkpoint

Date: 2026-09-21 KST. Implementation based on `8159a311625b81ffeac454e01d6a7bf72c8cdbc3`, isolated `feature/personal-c1-bounded-cleanup` / Draft PR #5. **Engineering candidate; NOT independently security-approved, signed release or deployed Business tool.**

## Behavioral contract
- `local_create_file` remains *new-file only* (O_EXCL). `local_replace_file` only accepts an EXISTING regular file plus an exact expected SHA-256 and new bounded UTF-8 bytes. Missing target, stale hash, target symlink/hardlink and parent symlink refuse.
- macOS `native-replace-cas.c` traverses parents using `openat(O_NOFOLLOW)`, opens old leaf without following links, hashes and identifies original file, creates owner-private uniquely named staging in the SAME directory, fsyncs it, re-checks target hash + dev/inode/size/mtime and commits with `renameat`; then fsyncs parent. File visibility is atomic. Existing mode bits (up to 0777) are preserved; ACL, xattrs, flags and other metadata are NOT preserved by this candidate. Existing files above 16 MiB are refused.
- `native-replace-cas.mjs` verifies the exact private binary SHA, private parent/file ownership/modes and postcommit SHA. Failures after a potentially committed rename, timeout, output mismatch or fsync uncertainty must be reconciled by checking the target; **never blindly retry**. Pre-commit stage cleanup only addresses the exact self-created named regular file.
- The expected-digest check and rename are NOT a single kernel CAS primitive. A hostile same-UID non-cooperating writer could alter the leaf between last check and rename or mutate a prior hard reference. Therefore do NOT claim adversarial race-free or linearizable hash CAS; this is a bounded conditional replacement for ordinary single-owner, quiescent files. Additional global locks or per-action approval were NOT introduced.

## Opt-in configuration and usability
- `L1_NATIVE_REPLACE_ENABLED=1`, `L1_NATIVE_REPLACE_BIN=<owner-private actual compiled helper path>`, `L1_NATIVE_REPLACE_SHA256=<actual helper binary SHA>` in the independent L1 strict/native-create profile. L0 `L1_NATIVE_REPLACE_ENABLED=1` advertises `local_replace_file` only when enabled, including in `PERSONAL_CORE_TOOLS=1` profile. When OFF, existing core remains 32 names; with replacement ON, core is 33 names. Default development 36-name inventory remains intact. No L1 effect is authorized by a presentation flag.
- Raised only file create/write/replace payload envelope limits to 350000 characters at the token-authenticated L0/L1 boundaries to accommodate up to 256 KiB UTF-8 text; other L0 calls remain 16 KiB and other L1 routes 8 KiB. File operation still enforces 262144 UTF-8 bytes.
